# LlamaIndex Practical - 1

## Assignment scope
Build a web application with LlamaIndex that:
- loads 20-30 CV files,
- splits CVs into meaningful chunks,
- generates embeddings,
- stores vectors in a vector DB,
- extracts candidate details,
- generates a summary of strongest skills and highlights,
- shows candidate list + detailed profile page in UI.

Dataset reference: https://www.kaggle.com/datasets/snehaanbhawal/resume-dataset

## Implementation in this repository

### 1. Loading CV files
- Source folder: `data/` (currently 25 CV PDFs).
- Loader: `SimpleDirectoryReader` in `app/data_pipeline.py`.
- Candidate ID is generated from file name using `slugify(...)`.

### 2. Splitting into chunks
- Chunking is performed with `SentenceSplitter(chunk_size=512, chunk_overlap=80)`.
- Implemented in `CandidateIndexer._build_nodes(...)` in `app/data_pipeline.py`.

### 3. Embeddings
- Embeddings are created by `create_embedding_model()` in `app/llm_provider.py`.
- Provider is configurable:
  - `LLM_PROVIDER=openai` -> `OpenAIEmbedding`
  - `LLM_PROVIDER=azure` -> `AzureOpenAIEmbedding`

### 4. Vector database
- Vector store: **ChromaDB** (`storage/chroma/`).
- Collection name: `candidates`.
- Implemented via `ChromaVectorStore` and `VectorStoreIndex` in `app/data_pipeline.py`.

### 5. Candidate details extraction
- `extract_candidate_details(...)` queries each candidate sub-index and extracts:
  - `name`
  - `profession`
  - `skills`
  - `years_experience`
  - `summary`
- Candidate model is `CandidateProfile` in `app/models.py`.
- Data is persisted to `storage/candidates.json` through `app/profile_store.py`.

### 6. Experience summary generation
- Summary is generated by LLM during extraction (`summary` field in JSON).
- Displayed in:
  - candidate list,
  - candidate details page,
  - agent responses.

### 7. Web application outcome
- Streamlit app entry point: `app/web.py`.
- Tabs:
  - `Agent Chat` (default tab),
  - `Candidate Directory`.
- Candidate profile page includes summary, skills, source file, and PDF preview/download.

### 8. Separation of concerns
- `app/data_pipeline.py` handles indexing workflow.
- `app/llm_provider.py` handles provider selection and model factories.
- `app/profile_store.py` handles profile persistence/loading and index-state checks.
- `app/models.py` contains reusable domain models.

## How to run

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Optional `.env` for OpenAI:

```env
LLM_PROVIDER=openai
OPENAI_API_KEY=...
OPENAI_LLM_MODEL=gpt-4o-mini
OPENAI_EMBED_MODEL=text-embedding-3-small
```

Build index:

```bash
python -m app.data_pipeline
```

Run web app:

```bash
streamlit run app/web.py
```
